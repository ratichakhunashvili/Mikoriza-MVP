# მიკორიზა (MIKORIZA) — პროტოტიპი

ორგანული ნარჩენის ჭკვიანი გადამუშავებისა და ვერმიკომპოსტირების სისტემის დიზაინ-პროტოტიპი:
საჯარო landing page და ოპერატორის პანელი **სატესტო მონაცემებით**.

> ეს არის დემო. რეალური სენსორები და მოწყობილობები მიერთებული არ არის, ყველა მაჩვენებელი და მართვა სიმულაციაა.

## გაშვება (Visual Studio Code)

საჭიროა [Node.js](https://nodejs.org) 18 ან უფრო ახალი.

1. გახსენით საქაღალდე VS Code-ში (`File → Open Folder`).
2. გახსენით ტერმინალი (`Terminal → New Terminal`) და გაუშვით:

```bash
npm install
npm run dev
```

3. ბრაუზერში გახსენით მისამართი, რომელსაც ტერმინალი აჩვენებს (ჩვეულებრივ http://localhost:5173).

- მთავარი გვერდი: `/`
- ოპერატორის პანელი: `/admin` (შესვლა საჭირო არ არის)

## ბრძანებები

| ბრძანება | რას აკეთებს |
| --- | --- |
| `npm run dev` | ლოკალური გაშვება განვითარებისთვის |
| `npm run build` | საბოლოო ვერსიის აწყობა (`dist/`) |
| `npm run preview` | აწყობილი ვერსიის გადახედვა |
| `npm run build:single` | ერთი HTML ფაილი (`dist-single/index.html`), რომლის გაზიარებაც მარტივია |
| `npm test` | ავტომატური ტესტები |

## Vercel-ზე განთავსება

პროექტის GitHub რეპოზიტორიის Vercel-ში იმპორტისას გამოიყენეთ ნაგულისხმევი პარამეტრები:

- Framework Preset: **Vite**
- Build Command: `npm run build`
- Output Directory: `dist`
- Install Command: `npm install` (ან Vercel-ის ავტომატური არჩევანი)

ეს პარამეტრები `vercel.json`-შიც არის მითითებული. მისი rewrite წესი უზრუნველყოფს, რომ `/admin`-ის მსგავსი აპლიკაციის მარშრუტები პირდაპირ გახსნისა და განახლებისასაც სწორად ჩაიტვირთოს.

## სტრუქტურა

```
src/
  pages/LandingPage/        საჯარო გვერდი
  pages/AdminDashboard/     ოპერატორის პანელი (მიმოხილვა, სექციები, მოწყობილობები, გაფრთხილებები, ...)
  components/brand/Logo.tsx ლოგო (დროებითი SVG, იხ. ქვემოთ)
  components/charts/        გრაფიკები
  components/ui/            ღილაკი, ფანჯარა, შეტყობინება და სხვა
  data/mockData/            სატესტო მონაცემები და სატესტო შეტყობინებების ნაკადი
  data/content/             ტექსტები (landing, სახელწოდებები)
  lib/adminStore.tsx        პანელის მდგომარეობა და მოქმედებები
  lib/mockAutomation/       ავტომატიზაციის წესების სიმულაცია
  types/                    ტიპები
  styles/                   სტილები
```

## ფერები და შრიფტები

ფერები `tailwind.config.js`-შია: `cream #E2D9CC`, `espresso #2E211E`, `umber #6D5E51`, `sand #B1AA99`, `olive #868375`.
გაფრთხილებებისთვის პანელში დამატებით გამოიყენება `brick` და `ochre`.
შრიფტები (Fraunces, Noto Sans/Serif Georgian) იტვირთება Google Fonts-იდან `index.html`-ში.

## ლოგოს ჩანაცვლება

ახლა გამოიყენება დროებითი SVG სოკო და წარწერა `src/components/brand/Logo.tsx`-ში.
ოფიციალური ლოგოს ჩასასმელად შეცვალეთ მხოლოდ ამ ფაილის შიგთავსი (მაგ. `<img src="/logo.svg" />`, ფაილი ჩააგდეთ `public/` საქაღალდეში).

## სატესტო შეტყობინებები

პანელში შესვლიდან დაახლოებით 7 წამში იწყება სატესტო შეტყობინებების ნაკადი (ჩანს ზარის ხატულაზე და ქვედა შეტყობინებაში).
ტექსტები: `src/data/mockData/notifications.ts`. ნაკადის შეჩერება შეიძლება ზარის ფანჯრიდან.
მიმოხილვის გვერდზე ქვემოთ არის „სატესტო სცენარები“ (ტენიანობის დაცემა, სენსორის გათიშვა და სხვა).

## სად დაემატება რეალური IoT და API

ახლა ყველაფერი ბრაუზერში მუშაობს. რეალურ სისტემაზე გადასასვლელად:

1. **მონაცემების წყარო.** `src/lib/adminStore.tsx`-ში `useTicker` ყოველ 5 წამში სიმულაციურ მაჩვენებლებს ანახლებს (`lib/mockAutomation/engine.ts`).
   ჩაანაცვლეთ ის API-დან ან WebSocket-იდან/MQTT-დან მიღებული ნამდვილი გაზომვებით და გააგზავნეთ იგივე `tick` ტიპის მოქმედება.
2. **სენსორების ისტორია.** `src/data/mockData/history.ts` აგენერირებს სატესტო გრაფიკებს. ჩაანაცვლეთ მონაცემთა ბაზიდან მიღებული ისტორიით.
3. **მოწყობილობების მართვა.** `toggleDevice` და `setDeviceMode` ახლა მხოლოდ მდგომარეობას ცვლის. რეალურ სისტემაში აქ უნდა გაიგზავნოს ბრძანება სერვერზე, რომელიც IoT კონტროლერს ელაპარაკება, და ინტერფეისი უნდა დაელოდოს დადასტურებას.
4. **ავტომატიზაციის წესები.** `engine.ts`-ის ლოგიკა რეალურ სისტემაში სერვერზე ან კონტროლერზე უნდა სრულდებოდეს, რომ ინტერნეტის გათიშვისას მუშაობა არ შეწყდეს. ინტერფეისი მხოლოდ წესებს აჩვენებს და ცვლის.
5. **უსაფრთხოება.** საგანგებო გამორთვა, უსაფრთხო რეჟიმი და მაქსიმალური მუშაობის დრო ახლა სიმულაციაა. რეალურ სისტემაში ისინი ფიზიკურ დონეზეც უნდა არსებობდეს (ადგილობრივი ამომრთველი).
6. **ავტორიზაცია.** ახლა პანელი პირდაპირ იხსნება. რეალურ ვერსიაში დაამატეთ შესვლა და როლების შემოწმება სერვერზე (`src/lib/permissions.ts` უკვე აღწერს ოთხ როლს).
7. **ტიპები.** `src/types/index.ts` არის ერთიანი მონაცემთა მოდელი: სექციები, სენსორები, მოწყობილობები, გაფრთხილებები. API-ის პასუხები ამ ფორმას უნდა მისდევდეს.
